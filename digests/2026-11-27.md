# Lume scout digest, 2026-11-27

Upstream merged two big renderer performance PRs (#364, #373), split here into five small rows. New native launcher Lounge has two cheap performance ideas. Twelve new rows (B122 to B133), plus two "also" links on B35 and B118.

## Worth borrowing

### B127 Keep compiled shaders on the TV (P2, Performance, Medium)
[lg-lounge shader.rs](https://github.com/YashwanthKamireddi/lg-lounge/blob/main/src/renderer/shader.rs)
Lounge, a new native Rust Home for rooted LG TVs, saves linked GL programs to flash (GL_OES_get_program_binary) so a cold start skips shader compiling. Faster startup (2) in one self-contained file, but it must fall back to compiling when a firmware update makes the saved copy invalid (1), hence Medium.

### B128 Give memory back while behind an app (P2, Performance, Medium)
[lg-lounge "Why it is fast"](https://github.com/YashwanthKamireddi/lg-lounge#why-it-is-fast)
When another app is on screen, Lounge frees its textures and trims the heap so the app gets the memory. Helps Plex and other apps (2); the cost is reloading artwork on return to Home, which needs a TV test so Home does not feel slower (1, 2).

### B129 Ignore small Magic Remote movements in ambient (P2, Stability, Low)
[HearthNG Quiet Mode Guard](https://github.com/emoorpheus/HearthNG#5-magic-remote-quiet-mode-guard)
HearthNG, a webOS launcher fork, ignores tiny pointer jitters so a resting Magic Remote does not wake hidden rows or break the ambient clock. Lume already has a pointer grace period on Home (B96); worth checking that ambient gets the same treatment (1, 8).

### B131 Custom picture for an input tile (P3, Feature, Low)
[couch-tv 9a00674](https://github.com/Seagey/couch-tv/commit/9a00674)
couch-tv lets an input tile (for example a PS5) show a picture you add yourself, falling back to the drawn icon. Lume already renames inputs and has a phone upload page, so this could reuse both; small but one more setting (3, 4).

### B132 Accent colours matched to the wallpaper (P3, Feature, Medium)
[NeonDeck for webOS](https://github.com/helldragonpz/neondeck-webos#neondeck-for-webos)
NeonDeck's Auto Theme picks icon and accent colours from the current wallpaper locally, with a saved manual override. Offline and opt-in, but it touches the shared colour paths and wallpaper changes (3, 7).

## Merge from upstream?

### B122 Smaller redraws while moving around apps and settings (P2, Performance, Medium)
[ecklf/lg-luma #373](https://github.com/ecklf/lg-luma/pull/373)
The damage tracker part of #373 repaints less of the screen during navigation. Builds on the partial-redraw work Lume already took in B109, so it is the cheapest part of the PR to take (2, 7).

### B123 Reuse identical vector vertices (P3, Performance, Medium)
[ecklf/lg-luma 9894712](https://github.com/ecklf/lg-luma/commit/9894712)
Repeated icon and text outlines share vertex data (vector.rs). Self-contained but a modest gain (2, 7).

### B124 Prepare app icons and focus labels while idle (P3, Performance, Medium)
[ecklf/lg-luma 9894712](https://github.com/ecklf/lg-luma/commit/9894712)
Installed app icons and focus labels are got ready in idle time. Related to B74 (scored 4 because it needs upstream's idle shadow code); this part touches app_artwork.rs and view.rs and may come apart from it, which needs checking (2, 7).

### B125 Simpler common paint operations, skip hidden glass (P3, Performance, Medium)
[ecklf/lg-luma 2994b4d](https://github.com/ecklf/lg-luma/commit/2994b4d)
Short shader paths for flat, folded and shadow paints, and glass hidden under opaque recent cards is skipped. Shader edits on shared code; the hidden-glass part is aimed at upstream's stacked recents (2, 7).

### B126 Bake resting glass interiors once per wallpaper (P4, Performance, High)
[ecklf/lg-luma 7c019aa (#364)](https://github.com/ecklf/lg-luma/commit/7c019aa)
Big win on webOS 5 Mali TVs (Settings glass from about 18 ms per frame down), but it only runs with upstream's specialised paint programs, which Lume does not have (B113). Deep renderer change (1, 7).

- [ecklf/lg-luma #411](https://github.com/ecklf/lg-luma/pull/411): docs only (compatibility tables, Home Chooser guidance). Nothing to take.

## Not for us

- **B133 Home Assistant indoor readings in ambient** ([webos-ambient 1dfe056](https://github.com/ryanrs-chang/webos-ambient/commit/1dfe056)): needs a network service and a stored token (5); the NAS widget in webos-home-launcher is the same idea and is linked on the row.
- **B130 Block LG firmware update pop-ups** ([HearthNG](https://github.com/emoorpheus/HearthNG#3-block-lg-ota-update-pop-ups-rooted-tvs)): changes a system service from the launcher (1, 9).
- [Mokto/tvlauncher](https://github.com/Mokto/tvlauncher/commit/60c84be): film player subtitles, offline library search, configurable Home tab and Settings redesign; all built around its media player and tabs (3).
- [Seagey/couch-tv](https://github.com/Seagey/couch-tv/commit/e001c17): TV settings slimmed, linking without codes, lazy Python imports in its bridge; tied to its phone/website setup, nothing self-contained for Lume.
- [adeze/lg-hue-sync](https://github.com/adeze/lg-hue-sync): Hue and Nanoleaf ambient light sync daemon; outside a launcher's job.
- [vibribbonee/panelcomfort-webos](https://github.com/vibribbonee/panelcomfort-webos): brightness schedules; LG system controls (9).
- [vibribbonee/luma-home-webos 2801903](https://github.com/vibribbonee/luma-home-webos/commit/2801903): Home Assistant address follow and release; network smart-home (5).
- [kapoko/webos-latest-news](https://github.com/kapoko/webos-latest-news), [sourabhkalebere-eng/LG-LJ573D-WebOS](https://github.com/sourabhkalebere-eng/LG-LJ573D-WebOS), [Va7dimar/lg-tv-native-os](https://github.com/Va7dimar/lg-tv-native-os): news launcher, IPTV suite and native-app research; nothing for Lume.
